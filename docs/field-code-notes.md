# incoPat 字段代码核对记录（结论在此，请勿反复核实）

> 本文件记录 **2026-09-22** 对 incoPat 官方《原始字段代码说明》的一次完整核对，以及
> **经数据库实测确认**的两组例外。写下来的目的是**避免以后一次次重新讨论同样的字段**——
> 看到这里的结论直接照用即可。

## 一、结论速览

| 项 | 数量 |
| --- | --- |
| 官方页面里出现的字段代码（含 HTML 注释与 JS 动态渲染的行） | 468 |

- Vim 插件：`incoPatSearchCriteria` → `syntax/incoPatSearchCriteria.vim` 的 `scKEY` 白名单
- dprint 插件：`dprint-plugin-incopat` → `src/parser/fields.rs` 的 `FIELD_CODES`

## 二、核对来源与方法

- 页面：<https://www.incopat.com/help/sysdoc/helpcode.html>（**需登录**；未登录访问只会返回官网首页）
- 页面结构：**9 张静态表（472 行）＋ 32 行由 `addHelpCodeHtml()` 用 JS 动态渲染**。
  解析时**两部分都要取**，只解析静态表会漏掉 `USE-CN`、`MBCLAS1`、`INDUSTRY-TYPE` 等一批字段。
- 方法：把页面另存为 HTML，解析每行「检索语法」列里的 `字段代码=`。

## 三、⚠️ 页面上看不到、但数据库可用的字段（**保留，不要删**）

### 3.1 只写在页面 HTML 注释里（浏览器渲染不出来）

这些行在页面源码里被 `<!-- ... -->` 包住，所以**肉眼在页面上确实找不到**：

| 字段代码 | 字段名 |
| --- | --- |
| `PHC` | 中国范畴分类 |
| `CHANGE-DC` | 变更入库时间 |
| `FAM-DC` | 同族信息更新时间 |
| `CP-DC` | 专利引证更新时间 |
| `FC-DC` | 专利被引证更新时间 |
| `CN-DC` | 非专利引证更新时间 |
| `REF-DC` | 引证整体更新时间 |
| `CUSTOMS-DC` | 海关备案最近更新时间 |

> `DOC-DC`（文档分类）同样只在注释里，但它本来就在字段清单中。

**维护者实测：在数据库中不报「不支持的字段」。→ 保留。**

### 3.2 页面上完全没有、但数据库可用的旧字段

| 字段代码 | 含义 | 官方页面对应写法 |
| --- | --- | --- |
| `APNORTT` | 申请人（标准化翻译） | 页面只有 `APNOR` |
| `AEENORTT` | 受让人（标准化翻译） | 页面只有 `AEENOR` |
| `PATENTEENORTT` | 专利权人（标准化翻译） | 页面只有 `PATENTEENOR` |

**维护者实测：这三个在数据库里确实能用。→ 保留。**

> 和 `(sen)` 同句算符属于同一类情况：官方网页撤掉了说明，但数据库仍然兼容。

## 六、以后官方又改了怎么重跑

1. 登录后把官方《原始字段代码说明》页面**另存为 HTML**。
2. 解析「检索语法」列得到官方代码集合 —— **记得同时取静态表和 `addHelpCodeHtml()` 里的行**。
3. 与 `FIELD_CODES` / `scKEY` 比对，按下面的规则处理差异：
   - **官方有、清单缺** → 先看它是不是在 HTML 注释里（§3.1）；在的话归入「保留」，不在的话补入。
   - **清单有、官方无** → 先看是不是 §3.2 里已知的兼容旧字段；不是的话去数据库实测，
     能用就补进 §3.2，不能用就删掉并记到 §4。
4. 改完把两个项目的字段数都确认成同一个数，并各自跑一遍测试。
